# AviUtl2プラグイン「テレビ演出」開発仕様書

## 1. プロジェクト情報

- プロジェクト名：SYNC_TV
- グループ名：SYNC
- 日本語プラグイン名：テレビ演出
- 使用言語：Delphi

## 2. 開発目的

AviUtl2上でテレビ番組の映像を自動生成するプラグインを作成する。

主に劇場動画や日常系動画などで、部屋の背景に配置されたテレビに動きのある映像を表示することを目的とする。

ユーザーが番組映像や動画素材を用意する必要はなく、プラグイン内部の描画処理によってテレビ番組を自動生成する。

テレビ番組そのものを鑑賞する用途ではなく、背景の一部として自然に見えることを重視する。ただし、拡大表示した場合でも極端に品質が低くならないようにする。

音声の生成および出力は行わない。

## 3. テレビ本体の描画

テレビ本体を描画するかどうかを切り替える設定を用意する。

### 本体描画なし

- 番組映像およびテレビ画面に関する演出のみを描画する。
- テレビ本体やスタンドなどは描画しない。
- 画面部分が透過されたPNG画像の背面に配置する使用方法を基本とする。
- 画面部分が透過されていない背景画像に直接重ねる使用方法にも対応する。
- 描画範囲外は完全透明とする。

### 本体描画あり

- 一般的な薄型液晶テレビを描画する。
- 黒色を基調とした細いベゼルを持つデザインとする。
- 特定メーカーの製品やロゴを再現しない。
- 電源インジケーターを設け、電源状態に連動させる。
- テレビ本体と番組映像は一体として座標、拡大率、回転などの変形を行う。
- ブラウン管テレビなどの特殊な形状には現段階では対応しない。

初期状態は本体描画なしとする。

## 4. チャンネル

「チャンネル」という整数値のパラメータを用意する。

チャンネル番号によって表示する映像およびテレビの電源状態を切り替える。

初期値は10とし、オブジェクトを追加した直後からテレビ番組が表示されるようにする。

チャンネル0～9は特殊表示用とし、10以降を通常の番組用に割り当てる。

### チャンネル割り当て

- 0：電源OFF
- 1：砂嵐
- 2：カラーバー
- 3：信号なし
- 4～9：将来の特殊表示用に予約
- 10：ニュース番組
- 11：天気予報
- 12：野球中継
- 13：サッカー中継
- 14：バラエティ番組
- 15：音楽番組
- 16：アニメ番組
- 17：料理番組
- 18：通販番組
- 19：ドラマ
- 20：CM

番組チャンネルは今後追加できる構造とする。

未実装または予約されたチャンネルが指定された場合でも、異常終了や描画異常が発生しないようにする。

## 5. 電源およびチャンネル切替演出

チャンネルの値が変化した場合は、その変化に応じて短時間のアニメーションを自動的に行う。

### 電源オン

チャンネル0から1以上に変化した場合。

- 黒画面から短時間で番組映像を表示する。
- 画面の明るさを変化させ、液晶テレビの電源が入ったように見せる。
- 本体描画時は電源インジケーターも連動させる。

### 電源オフ

チャンネル1以上から0に変化した場合。

- 番組映像を短時間で暗くし、消灯状態の画面に移行する。
- 電源OFF中はテレビ画面を消去するのではなく、消灯した液晶画面として描画する。
- 周囲の明るさに応じて画面の黒色や光沢を変化させる。

### チャンネル切替

チャンネル1以上から別のチャンネル番号に変化した場合。

- 一瞬黒画面を表示するなど、テレビのチャンネルを切り替えたような演出を行う。
- 切替後は新しいチャンネルの映像を表示する。

これらのアニメーションは0.2～0.5秒程度を目安とする。

演出時間を設定する専用パラメータは設けず、内部処理によって自然な演出を行う。

液晶テレビを想定するため、通常の電源操作時にブラウン管特有の画面収縮などは行わない。

## 6. 基本描画パラメータ

AviUtl2標準オブジェクトの描画パラメータを参考にし、名称、並び順、操作方法、数値の意味を可能な限り統一する。

以下のパラメータを用意する。

| パラメータ | 初期値 |
|---|---:|
| X | 0.00 |
| Y | 0.00 |
| Z | 0.00 |
| 中心X | 0.00 |
| 中心Y | 0.00 |
| 中心Z | 0.00 |
| X軸回転 | 0.00 |
| Y軸回転 | 0.00 |
| Z軸回転 | 0.00 |
| 拡大率 | 100.000 |
| 縦横比 | -43.750 |
| 透明度 | 0.00 |

AviUtl2標準の描画機能で実現できるものについては、重複した変形処理やパラメータを設けないこと。

### 縦横比

初期状態の画面は横16：縦9とする。

縦横比の計算方法はAviUtl2標準の図形オブジェクトを参考にする。

0を正方形とし、マイナス方向を横長、プラス方向を縦長とする。

- -75.00：4:1
- -50.00：2:1
- -43.75：16:9
- -25.00：4:3
- 0.00：1:1
- 25.00：3:4
- 43.75：9:16
- 50.00：1:2

初期値は-43.75とする。

縦横比を変更した場合は、番組映像、画面形状、テレビ本体なども整合性を維持すること。

### 3D回転

X軸、Y軸、Z軸の回転に対応する。

斜め方向から見たテレビにも自然に映像を合わせられるよう、遠近感を伴った変形を行う。

単純な平面回転や横幅の縮小だけで代用しないこと。

### 四隅補正

縦横比や各軸の回転だけでは背景画像のテレビ画面に合わせられない場合に備え、画面四隅の位置を個別に補正できる機能を用意する。

通常の利用時は縦横比と回転によって位置を合わせ、必要な場合のみ四隅補正を使用する。

初期状態では四隅補正を行わない。

### 透明度

AviUtl2標準と同様に、0で完全表示、100で完全透明とする。

## 7. テレビ専用パラメータ

| パラメータ | 初期値 | 内容 |
|---|---:|---|
| チャンネル | 10 | 番組および電源状態 |
| テレビ本体描画 | OFF | 本体の描画有無 |
| 角丸 | 0.00 | 画面四隅の丸み |
| 周囲の明るさ | 50.00 | 周囲の環境光 |

基本描画パラメータとテレビ専用パラメータはグループ分けを行う。

数値パラメータは、チャンネルなどの整数指定が必要なものを除き、可能な限り細かな調整ができるようにする。

### 角丸

画面四隅の丸みを調整できるようにする。

0の場合は通常の長方形とする。

背景画像のテレビ画面に直接重ねる場合に、画面の形状に合わせて調整できるようにする。

角丸によって除外された部分は透明とする。

## 8. 周囲の明るさ

明るい部屋に設置されたテレビと、暗い部屋に設置されたテレビでは見え方が異なるため、「周囲の明るさ」という専用パラメータを用意する。

- 設定範囲：0～100
- 初期値：50
- 設定単位：0.01
- 0：暗い環境
- 100：明るい環境

単純に映像全体の輝度を変更するだけではなく、環境光に対する液晶テレビの見え方を再現する。

### 明るい環境

- 番組映像は環境光によって若干淡く見えるようにする。
- 画面表面の光沢や反射を適度に強調する。
- 電源OFF時も画面が完全な黒にならず、周囲の光を反射しているようにする。
- テレビ本体の輪郭を明瞭にする。
- 画面周囲への光漏れは目立たないようにする。

### 暗い環境

- 番組映像が発光しているように見せる。
- 画面表面への環境光の反射は弱くする。
- 電源OFF時はほぼ黒色とする。
- テレビ本体は暗く目立たないようにする。
- 番組映像の色や明るさに連動した周囲への光漏れや発光表現を行う。

環境光の影響は過剰にならないようにし、背景画像と自然に合成できることを重視する。

## 9. テレビ番組の自動生成

各チャンネルは独立した番組描画処理を持つものとする。

外部の画像ファイルや動画ファイルをユーザーに要求しないこと。

人物、背景、テロップ、図形、スポーツ選手、スタジオなどは内部処理によって描画する。

### ニュース番組

- ニューススタジオ
- ニュースキャスター
- キャスターの口や手などの動き
- ニュース映像への切替
- ニューステロップ
- 画面下部のニュース速報表示

### 天気予報

- 天気予報スタジオ
- 日本地図などを使用した天気表示
- 晴れ、曇り、雨、雪などの天気マーク
- 気温や降水確率の表示
- 解説者による指示動作
- 予報画面の切替

### 野球中継

- 野球場
- 投手、打者、野手などの動き
- 投球、打撃、走塁、守備
- スコア表示
- カメラアングルの切替

### サッカー中継

- サッカー競技場
- 選手やボールの移動
- パス、ドリブル、シュート
- ゴール時の演出
- スコアおよび試合時間の表示
- カメラアングルの切替

### バラエティ番組

- カラフルなスタジオ
- 複数の出演者
- 出演者のリアクション
- 大きなテロップ
- ワイプ表示
- 場面切替

### 音楽番組

- ステージ
- 歌手や演奏者
- 歌唱や演奏を行っているような動き
- ステージ照明
- カメラアングルの切替

音楽番組についても音声は生成しない。

### アニメ番組

- デフォルメされたキャラクター
- キャラクターの移動や会話
- 背景の切替
- 日常シーンやアクションシーン

### 料理番組

- キッチンスタジオ
- 料理を行う出演者
- 食材や調理器具
- 切る、混ぜる、焼くなどの調理動作
- 料理の完成画面

### 通販番組

- 商品紹介
- 商品を説明する出演者
- 価格表示
- 商品の拡大表示
- 商品や説明画面の切替

### ドラマ

- 複数の登場人物
- 会話シーン
- 人物の移動や表情変化
- 屋内外の背景
- カメラアングルの切替

### CM

- 架空の商品やサービスの紹介
- 商品画像風の描画
- キャッチコピー
- 短時間で切り替わる複数のシーン
- CMの種類そのものも時間経過によって変化させる

## 10. 番組映像の品質

背景に配置された小さなテレビであっても、何の番組を放送しているのか視覚的に認識できることを重視する。

- 番組ごとに明確に異なる画面構成と配色を採用する。
- 人物や背景を単純な図形の集合だけで表現しない。
- 人物の動きは可能な限り自然にする。
- テロップやスコアなど、番組を特徴づける表示を積極的に使用する。
- 実際のテレビ番組のようにカメラアングルや場面を切り替える。
- 同じ構図や同じ動きを長時間繰り返さない。
- 短いループアニメーションを単純に繰り返すだけの構成にしない。
- 長時間表示した場合でも、番組が進行しているように見せる。
- 実在する放送局、企業、番組、キャラクター、商品などのデザインは使用しない。
- 番組名、商品名、テロップなどは架空のものとする。

映像を小さく表示することを理由に描画品質を落とさないこと。

## 11. 時間管理と再現性

AviUtl2上での動画編集およびエンコードを前提とした時間管理を行う。

- 番組の進行はAviUtl2のフレーム位置および時間に基づいて決定する。
- 実時間や描画処理の呼び出し回数に依存しない。
- 同一条件、同一フレームでは同一の映像を生成する。
- 任意のフレームへの移動、逆方向への移動、繰り返し再生に対応する。
- プレビューとエンコードで演出内容が異ならないようにする。
- 乱数を使用する場合は再現性を確保する。
- 電源オン・オフおよびチャンネル切替演出も、フレーム位置から正しく再現できる構造とする。
- チャンネル切替を再現するために、直前の描画呼び出し時のチャンネル値だけに依存する実装は行わない。

AviUtl2 SDKで取得可能な情報を確認し、チャンネル変更時点を正しく扱える方法を検討すること。

## 12. 描画処理およびパフォーマンス

描画にはDirect2Dを使用することを基本とする。

- 番組映像の生成処理とテレビ画面への変形・合成処理を分離する。
- 番組ごとに描画処理を独立させる。
- 新しいチャンネルを容易に追加できる構造とする。
- 共通する人物描画、背景描画、テロップ描画、アニメーション処理などは適切に共通化する。
- 描画リソースや静的な画像のキャッシュを活用する。
- 同じ素材を毎フレーム不要に生成しない。
- 描画品質と処理速度の両立を図る。
- 番組映像の生成解像度は、描画品質を維持しつつ過剰な処理負荷が発生しないようにする。
- 透明度、角丸、遠近変形、環境光などの処理によって描画品質が損なわれないようにする。
- 複数のテレビ演出オブジェクトを同時に配置した場合にも対応する。

## 13. 開発方針

既存のSYNCシリーズのプラグインを参考にし、AviUtl2との連携方法、描画処理、パラメータ管理、プロジェクト構成などは可能な限り統一する。

まずテレビとしての共通機能、チャンネル管理、電源演出、画面変形、環境光表現を確立する。

その後、各番組チャンネルの描画およびアニメーションを実装する。

番組ごとの品質を個別に確認し、単調なアニメーションや不自然な描画がある場合は改善する。

単に映像が動いているだけではなく、実際にテレビ番組が放送されているように見えることを完成条件とする。
